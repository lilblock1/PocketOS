# Phase 3A — native music player initial playback
Streaming RIFF PCM WAV mono/stereo, 16-bit and packed 24-bit, 8–192 kHz, no full-track buffering. Fixed 8 KiB audio input buffer, bounded chunk traversal, validates RIFF length and frame alignment, rejects unsupported format/truncated files. --probe and --decode do not open hardware; --decode writes raw PCM to stdout with optional squared software gain (100 lossless identity; 0 silence). --allow-play delegates to existing /usr/bin/aplay with raw ALSA parameters, default route only. No direct register/mixer writes. UI requires --allow-audio and an installed /usr/bin/pocketos-music with verified aplay/ALSA. Shell lists up to 32 regular WAV files in /mnt/sd_0/Music (one directory); Play, Pause/Resume, Stop and previous/next selection when idle; output is allowed only for headphone preference, capped at 50% target in UI. Playback process runs only while requested, continues across pages, controls via nonblocking pipe, pause stops supplying PCM but aplay may drain buffered audio and underrun. It is not calibrated for safe headphone SPL: verify hardware gain with no headphones before testing. No actual route selection, device installation, gapless playback, FLAC/MP3/other codecs, metadata or recursive indexing yet. No daemon, filesystem writes or Linux rebuild. Host fixtures cover byte-exact 16/24-bit PCM, mute, attenuation and malformed data. MIPS compile/version check uses prebuilt paired SDK if present. Real ALSA and touch handling are not verified.

## Phase 3A.2: optional compressed audio
Native PCM WAV remains unchanged. When separately installed at /usr/bin/ffmpeg, an on-demand decoder accepts FLAC, MP3, AAC, M4A/MP4, Ogg Vorbis and Opus. Output is normalized to stereo 48 kHz signed 16-bit PCM for compatibility; this is not bit-perfect high-resolution FLAC playback. Decoder uses bounded input probing, one requested decoder/filter thread, a 16 MiB single-allocation ceiling (not an overall memory cap), an 8 KiB shell audio pump and a pipe rather than a temporary full-song file. No executable is bundled or downloaded at runtime. Target FFmpeg, ALSA dependencies and actual RAM/performance need verification; host fixtures decode all formats and compare 48 kHz stereo 16-bit FLAC byte-for-byte. The library scans up to 2048 entries and 128 tracks, six nested levels, sorts relative names and rejects symlinks. Sequential auto-advance and active next/previous use process restart, not gapless playback. Physical audio is still opt-in. No metadata, artwork, playlist editor or shuffle yet.


## Phase 3A.3 — broader decoder format map
The fortified GCC buffer diagnostic is addressed by a separately bounded 4096-byte decoder read scratch buffer and checked copy into the 8192-byte PCM pump. A shared extension map keeps library discovery and decoder selection synchronized: WAV (native 16/24-bit PCM), FLAC, ALAC in M4A/MP4, MP3/MP2, AAC, Ogg Vorbis/Opus/Speex, WMA/ASF, APE, AIFF, WavPack, TTA, Musepack, AC3/EAC3, DTS, DSF/DFF, CAF, AU, AMR, 3GP, Matroska/WebM, RealAudio, TAK, VOC, Wave64, MLP/TrueHD, DVD-Audio container and ATRAC container candidates. Each optional format depends on a compatible FFmpeg demuxer and decoder; not all combinations are supported or tested. DSD is PCM conversion only and never native DSD/DoP. Host fixture coverage targets common encoder-available formats plus ALAC, but APE, Musepack, DSF/DFF and other decoder-only formats still need real fixtures. No DRM bypass, remote media, or device decoder package. The native PCM WAV path deliberately does not fall back on malformed files. The target decoder needs a size-optimized build and device RAM benchmarks.

## Phase 3A.4 — Now Playing and library controls
Now Playing displays optional local per-track sidecars: <filename>.tags (title=, artist=, album=, duration= integer seconds) and <filename>.ppm (exact P6, 64 x 64 RGB, 12288 bytes of pixels). Fallback is filename and a music icon. Embedded tag/art extraction is not yet bundled. Native WAV duration is reported by playback; position is measured at the PCM pipe write (not actual DAC presentation). Compressed duration requires sidecar; restart-based seek uses decoder -ss. Seeking is seconds granularity, not gapless. Engine reports progress via an optional inherited nonblocking descriptor, two native-endian uint32 words position/duration. No extra daemon. Now Playing button opens track screen. Library allows 512 tracks, 8192 visited directory entries and six levels; LIST toggles the user-supplied relative Music/playlist.m3u versus library. No playlist UI editor yet. Shuffle chooses a different random track; repeat all and repeat one are session state. Optional FFmpeg target binary is not bundled and no SD executable is automatically activated. Host CI tests native seek plus prior fixture coverage. Actual playback, device RAM, gapless and decoder packaging remain pending.

Desktop sidecar generator: run python apps/prepare-music.py PATH_TO_SD/Music with ffprobe and ffmpeg installed. It extracts existing embedded tags and one attached picture, writing only missing sidecars in the SD music folder; files without usable tags/art fall back to filenames/icon. User playlists can be made on PC as Music/playlist.m3u, one path relative to Music per line. Optional decoder deployment is still gated on a signed and verified MIPS package and safe application activation. No target executable has been built in this phase.

## Phase 6 development: audio routes (not hardware verified)
The routing policy now prioritizes a verified wired output over a verified Bluetooth audio sink and otherwise declines to choose a route. A Bluetooth control connection by itself is *not* proof of a functional A2DP sink. Route volumes are separately represented and capped at 50% in the policy. The policy has exhaustive presence-state unit fixtures. This policy is not yet connected to a live jack-event or A2DP state observer; no automatic switching is claimed.

The PCM player accepts explicit `--output wired` and `--output bluetooth` only in `--allow-play` mode, selecting the fixed ALSA aliases `pocketos_wired` and `pocketos_bluetooth`. It rejects arbitrary ALSA device strings, and legacy playback still selects `default`. The UI Bluetooth preference can request the fixed Bluetooth alias, but **it will not play until the hardware-appropriate Bluetooth PCM bridge and trusted ALSA configuration are installed and tested**. No Bluetooth bridge is shipped or started. USB remains unavailable.

Run `sh hardware/hiby-r1/audio-route-probe.sh` on an R1 to gather a read-only audio interface report (no sound or radio changes). Determine the actual wired jack event provider, headphone/speaker mixer route, Bluetooth A2DP transport and ALSA alias mapping before implementing a low-power event subscriber and seamless handoff. Software attenuation is not a calibrated listening-level protection. Do not publish a flashable build on the strength of host tests alone.

### Read-only event monitor (Phase 6 prototype)
`pocketos-audio-monitor --status` reports `wired=ready`, `wired=absent` or `wired=unknown` using Linux `EV_SW/SW_HEADPHONE_INSERT`, if a readable event device publishes that switch. `--watch` follows changes using `poll()` and rescans every five seconds for hotplugged event nodes. There are no hardware writes or audio playback. Unknown is deliberately distinct from unplugged; the R1 may use a vendor-specific mechanism instead of EV_SW. This monitor is built and host-smoke-tested, but it is **not yet integrated with the player process** and no automatic switching is active.

The R1 documentation indicates Bluetooth output support, but the actual PocketOS A2DP-to-ALSA transport and configured aliases remain prerequisites before enabling Bluetooth routing.
