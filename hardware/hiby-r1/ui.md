# Phase 2F: PocketOS shell

Native C framebuffer shell with a modern dark card grid, mint accent, status bar, settings navigation, system diagnostics and battery display. Uses a single 240x320 RGB565 canvas (153600 bytes), a tiny built-in uppercase bitmap font, integer-only rendering and no framework, GPU, compositor, animation loop or extra dependencies. The native backend reads framebuffer geometry, line stride and RGB bitfields and scales with letterboxing. It accepts an explicitly selected evdev device; touch ranges are read via ioctl, and navigation keys are supported. It blocks on poll and redraws only on navigation/status changes; battery sampling occurs after 30 seconds without input. No automatic startup service yet.

Host rendering and navigation tests: make -C apps check. Preview: pocketos-shell --preview HOME home.ppm (also SETTINGS, SYSTEM, BATTERY, MUSIC). CI uploads PPM images and cross-compiles the shell when a matching SDK exists. The native framebuffer/input paths have not been hardware-tested; touch orientation, device selection and multiple input devices remain integration gates. The status and navigation work; music, books, games, filesystem and various settings services are explicitly not yet connected. Font accessibility, themes, boot animation and Wi-Fi updater remain future work. No flashable firmware or boot enabled.

## Phase 2G
Tap the status bar or swipe down from it to open Quick Controls; swipe up or tap Close to return. Menu key is a keyboard fallback. Wi-Fi and Bluetooth show detected interfaces, brightness is a read-only percentage when one backlight is available, and volume is explicitly not connected. Tapping a hardware tile opens its settings page; no hardware writes are performed. The battery-saver tile selects a preference, not applied power policy. Preferences offer dark, light and high-contrast themes, 12/24-hour local time, and higher-contrast text (not a dyslexia-specific font). Native mode can store preferences atomically with --config /absolute/existing/writable/directory/ui.conf --fb /dev/input/eventN; without that flag they are session-only. No userdata mount or format is attempted. System timezone setting, actual brightness/volume/radio control and physical touch validation remain pending. CI previews include CONTROL and PREFERENCES.
