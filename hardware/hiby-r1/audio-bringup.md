# Phase 5: playback bring-up

The user reported Playback unavailable on the second physical PocketOS build. The staged candidate had ALSA aplay/amixer but no `etc/pocketos/features` or optional decoder, and the startup supervisor does not enable audio by default. This explains a possible lock; the physical runtime command line and current mixer values still need inspection. Headphone switch 0/1 was verified physically; the previously observed card is `hibysoundcard`, device 0.

The next development revision supports a separate protected `etc/pocketos/audio-enable` file containing exactly `POCKETOS-R1-AUDIO-1` plus LF (root-owned, mode 0400 or 0600). This adds `--allow-audio` without enabling networking or unrelated feature gates. It is not installed automatically. The shell reports locked, missing decoder, invalid file, missing headphones, route failure, or PCM failure instead of a generic unavailable message. Jack state must be 1 to start or resume hardware playback. While playing, the shell checks jack state at most every 500 ms of idle time and pauses on unplug/unknown, without auto-resume. PCM targets the known named ALSA card through plughw instead of the unspecified default; this may perform format conversion and is not a bit-perfect guarantee. The prior conservative attenuation and output route writes remain, pending validation; the unused register-write attribute is no longer a prerequisite. Playback gain is bounded to 50% in the engine as well as the UI. No new raw register or mute writes. Physical gain/SPL, output route, and actual audio remain unverified. Start testing with a quiet PCM WAV and headphones off the ears.

Read-only diagnostic on the current physical build: inspect `ps w`, `/etc/pocketos/features`, `/etc/pocketos/audio-enable`, `/run/pocketos-ui/shell.log`, `/sys/class/sound/card0/id`, `aplay -l`, `amixer -c 0 contents`, `/sys/class/switch/headset/state`, and the decoder status. No flash operation or firmware build is part of this revision. Compressed files still need the separately verified SD decoder/RAM activation path. Never execute unverified code from SD.
