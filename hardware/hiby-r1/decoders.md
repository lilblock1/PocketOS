# Phase 3F — optional audio-only decoder
Native WAV remains independent. A dedicated CI job builds pinned FFmpeg 7.1.5 from its authenticated upstream source (release signing key fingerprint verified), with an audio-only codec/demuxer allowlist, single PCM encoder, local file/pipe protocols and no network/external codec packages. Host and matching MIPS SDK builds use separate output directories; the target uses the verified reference-matched SDK, not an arbitrary cross compiler. Common compressed formats are tested against generated sample PCM; many additional formats are configured but not yet exercised. Compressed output is stereo 48 kHz signed 16-bit PCM, not bit-perfect high-resolution/DSD; no hardware decode yet.

The candidate stays outside the base Linux filesystem. A trusted integrator places pocketos-ffmpeg on /mnt/sd_0/PocketOS-codecs/ and provisions the digest in protected /etc/pocketos/decoder.sha256 out-of-band (never trust a digest downloaded from SD alone). pocketos-decoder activate requires root, actual mounted SD and /run tmpfs, protected directories, 12 MiB binary cap, 16 MiB free RAM headroom, and a bounded copied snapshot matching the trusted digest. The executable is cached in root-only RAM, not run from writable SD; inactive cache falls back to trusted /usr/bin/ffmpeg or fails compressed playback cleanly. Activation is manual, not yet wired to update selection or boot. Cache disappears on reboot. No flash writes. The SD binary is persistent; the separate RAM snapshot increases memory usage by the actual binary size while cached. A full 64 MiB device under memory pressure may reject activation. SHA-256 is an integrity control with independently trusted provisioning, not automatic signed-package activation. No signing key is provisioned. Do not use development artifacts as firmware.

SDK currently absent: previous Linux run predates SDK export. Host build can proceed; MIPS job is conditional on a matching successful foundation + compiler export. One explicit SDK-export foundation run is needed unless a matching SDK is recovered. No Linux build is automatically started by this phase. Output contains source, build configuration, license and relinking materials for development; public redistribution compliance review remains before release. ALSA aplay and actual audio route remain separate target blockers. No physical tests or performance measurements.
