# Phase 5C: guarded Wi-Fi bring-up
The captured physical PocketOS boot reported only loopback; the reference used wlan0. The new offline staging tool validates exact reference driver hashes, board power module, and operator-reviewed firmware/NVRAM hashes before copying up to 4 MiB of Wi-Fi core files into a disposable R1 firstboot tree. No vendor binaries are committed. A reviewed manifest with matching bin/txt pairs from the exact reference is still needed. Do not guess the chip or substitute firmware.

`python3 tools/stage-r1-wifi.py ROOT REFERENCE_ROOT REVIEWED_MANIFEST REPORT` runs after reviewed firstboot preparation; the generated marker enables the service only in this development tree. Use a disposable tree, never a live device filesystem. The helper verifies staged hashes at startup, requires the correct kernel, loaded radio power module and private tmpfs state, and starts brcmutil/brcmfmac and an isolated supplicant only on explicit scan/connect. No boot service, password persistence, DHCP or automatic connection. A custom test socket bypasses service startup. Existing stock supplicant sockets and unexpected state are rejected. The helper refuses stale state until manually inspected; no automatic module unload, shared radio reset or recovery/flash writes.

Offline tests exercise staging, missing markers, mismatched firmware pairs, tampering and non-overwrite. Physical SDIO, firmware identity, association, DHCP, DNS and HTTPS must still be verified. This is source only, not firmware or a release; the full local Phase 5 prerequisites must be synchronized before integration.
