# Phase 5: Smart Sleep (software-only)
Physical HiBy R1 tests reported `freeze standby mem` and enabled GPIO wakeup; all three kernel sleep states failed to wake (black screen and no USB ADB). Do not retry or enable kernel sleep until the board wake/resume path has been investigated. The old `--allow-suspend` and `suspend-enable` marker no longer enable anything.

The verified jack switch is `/sys/class/switch/headset/state`: 0 = unplugged, 1 = plugged, anything else = unknown. Smart Sleep listens to the unique `md-gpio-keys` device advertising KEY_POWER. A 30–800 ms press on release toggles manual backlight-off and interface idle; long press is untouched. Only a trusted root-owned `/etc/pocketos/smart-sleep-enable` with `POCKETOS-R1-SMART-SLEEP-1` enables it via `--allow-smart-sleep`. No marker installed by default. No sysfs kernel suspend, clock or regulator writes. Existing optional adaptive governor policy can be reused if explicitly enabled; no forced frequency reduction. The shell remains available to receive the next power key, ignores touch gestures while asleep, and suppresses UI rendering, clock/status sampling and unrelated polling. Other system processes are not frozen. Brightness is restored on wake/normal shell termination; losing the power input triggers wake or shell exit rather than remaining blank. Updates, book preparation and radio operations block entry; file operations are synchronous and known independent update/start locks also block entry. No guarantees for independently launched privileged writes.

Headphone-route music keeps playing only when the switch reports 1. While playing asleep, switch state is checked at least every 500 ms under normal scheduling; absent/unknown triggers a pause command, with a stop fallback if the control pipe fails. Already paused playback remains paused, and insertion or wake does not resume it automatically. Volume controls remain available during headphone playback. Audio output may drain buffered PCM after pausing. No Bluetooth audio handling, DAC power-off or physical audio validation yet. On stop fallback the last reported position is retained, not an exact DAC position. This saves display/UI work but is not suspend-to-RAM and battery savings remain unmeasured.

Host tests cover short/long/repeat/dropped power events, jack decoding, headphone-route policy, pause commands and no auto-resume, marker gating and stale-marker rejection. Physical test with a recoverable RAM-only UI and a working ADB session before enabling in any firmware: confirm unique power input, repeat sleep/wake with no playback, next test wired playback and unplug, check transfers and measure current drain. Current playback is still unavailable on the device and must be fixed before that test. No new firmware or device writes in this change.
